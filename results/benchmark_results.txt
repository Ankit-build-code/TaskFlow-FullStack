========================================================================
  Complexity Summary
========================================================================
  insertion_sort : best O(n)   | worst O(n^2)
  binary_search  : best O(1)   | worst O(log n)
  linear_search  : best O(1)   | worst O(n)

  Sort-first analysis (see README for full write-up)
  --------------------------------------------------
  At n=3000, insertion_sort performs ~4.5M comparisons.
  binary_search then finds any target in <=12 comparisons.
  linear_search on unsorted averages n/2 = 1500 comparisons per query.
  For Q queries between re-sorts: sort-first wins when Q > n/log2(n).
  At n=3000 the break-even is ~273 queries -- easily exceeded daily.
